## 1. 배경 및 목적

Phase 1(module-1~9)에서 연차·근태·결재·업무보고 데이터가 시스템에 축적되기 시작했다. 그러나 다음 두 가지 실무 니즈가 아직 해소되지 않았다.

1. **데이터 반출 불가**: 인사팀·팀장이 연차 사용 현황이나 근태 이력을 엑셀로 받아 별도 보고서를 만들거나 감사 자료로 활용할 방법이 없다.
2. **위임의 실효성 부족**: 결재자가 휴가 등으로 대결자를 지정해도, 대결자는 스스로 결재함에 들어가 보지 않는 한 자신에게 처리할 건이 있다는 사실을 알 수 없다. 알림(module-8)이 원 승인자에게만 가고 대결자에게는 가지 않기 때문이다.

## 2. 핵심 기능 정의

### 2.1 통계/리포트 다운로드

| 구분 | 내용 |
|---|---|
| 형식 | CSV(엑셀에서 바로 열림) — 별도 라이브러리 설치 없이 Node 내장 기능만으로 구현 가능하며, 로컬 파일 저장소 방침과 일관성 있음. 진짜 `.xlsx` 바이너리는 Design 단계에서 아키텍처 옵션으로 비교 후 필요 시 전환 |
| 데이터셋 1 — 연차 사용 내역 | 본인: 본인 신청 이력 전체 다운로드 / ADMIN: 부서·기간 필터로 전 직원 다운로드 |
| 데이터셋 2 — 근태 이력 | 본인: 월별 출퇴근 기록 / ADMIN: 전 직원 월별 요약+상세 |
| 데이터셋 3 — 결재 이력 | 본인이 상신한 건(전체 문서유형 통합) / 결재자: 본인이 처리한 건 |
| 권한 원칙 | 본인 데이터는 본인만, 전사 범위 데이터는 ADMIN만(module-5 근태 조회 권한 원칙과 동일하게 적용) |
| 진입 경로 | 각 화면(연차/출퇴근/결재함)에 "CSV 다운로드" 버튼 추가 — 별도 통합 리포트 화면은 이번 범위에서 제외(필요성 확인 후 후속 검토) |

### 2.2 위임/대결 고도화

| 구분 | 내용 |
|---|---|
| 대결자 알림 | 대결 기간이 시작되어 실제로 처리할 결재 건이 생기면(현재 module-8 `notifySubmitted`가 원 승인자에게만 가는 것을) 대결자에게도 SUBMITTED 알림이 가도록 확장 |
| 결재 이력 가시성 | 결재 상세/이력에서 "정민아 팀장(대결: 이하준)"처럼 실제 처리자와 대결 여부를 명확히 표시(현재 `ApprovalStepLog.action=DELEGATE` 데이터는 있으나 UI 미노출) |
| 위임 이력 조회 | 대결 지정 화면에서 과거(만료된) 위임 이력도 조회 가능하도록 확장(현재는 현재/미래 건만 표시) |
| 위임 범위 제한(선택) | 문서유형별로 위임 여부를 제한할지는 Design 단계에서 실제 필요성 확인 후 결정 — 이번 Plan에서는 필수 요구사항으로 확정하지 않음 |

### 2.3 (설계 방향만 기록 — 이번 사이클 구현 제외)

| 항목 | 결정 방향 | 비고 |
|---|---|---|
| 그룹웨어/메신저 연동 | Slack Incoming Webhook 방식. 관리자가 회사 설정에 Webhook URL을 등록하면 결재 이벤트를 Slack으로도 전송. URL 미설정 시 앱 알림만 정상 동작(옵션 기능) | 실제 Slack 워크스페이스 필요 — 사용자가 나중에 Webhook URL을 발급받아 설정 |
| 모바일 알림 | 네이티브 푸시(FCM/APNs) 대신 **브라우저 Web Push**로 대체 — 이 로컬 데모 환경에서 직접 브라우저로 검증 가능 | 이번 사이클엔 미포함, 다음 사이클 후보 |

## 3. 비기능 요구사항

| 항목 | 내용 |
|---|---|
| 다운로드 권한 | 본인 데이터 본인만 / 전사 범위 ADMIN만 — API 레벨에서 강제(module-5 근태 조회 권한 패턴 재사용) |
| 파일 인코딩 | CSV는 UTF-8 BOM 포함(엑셀에서 한글 깨짐 방지) |
| 알림 중복 방지 | 대결자 알림 추가 시, 원 승인자에게 가던 기존 알림과 별도 레코드로 남기되 동일 이벤트에 대해 중복 발송하지 않도록 설계 |
| 회귀 검증 | `scripts/smoke-test.mjs`에 리포트 다운로드·대결자 알림 시나리오 추가 |

## 4. 기술 스택

Phase 1과 동일(Next.js API Routes + 로컬 파일 저장소, bkend.ai 미사용). CSV 생성은 외부 라이브러리 없이 문자열 조립으로 구현하여 의존성을 늘리지 않는다.

## 5. 데이터 모델 변경(초안 — Design 단계에서 확정)

- 신규 테이블 없음 — 기존 `LeaveRequest`/`AttendanceRecord`/`Approval`/`DelegateAssignment`/`Notification`을 조회·가공만 하는 범위
- `CompanySettings`에 `slackWebhookUrl: string | null` 필드 추가 검토(§2.3, 이번 사이클 미구현이므로 스키마만 여지를 남김)

## 6. 화면 목록 초안

1. 연차 신청 내역 — "CSV 다운로드" 버튼 추가
2. 출퇴근(월별 조회) — "CSV 다운로드" 버튼 추가(본인/ADMIN 전 직원)
3. 결재함 — "처리 이력 CSV 다운로드" 버튼 추가, 목록에 대결 여부 배지 추가
4. 대결자 지정 — 과거 이력 탭 추가

## 7. 리스크 및 고려사항

- CSV vs 진짜 xlsx: 엑셀에서 CSV를 열면 숫자/날짜 서식이 의도와 다르게 보일 수 있음(예: 연차 일수 0.5가 그대로 보이는지 확인 필요) — Design 단계에서 샘플 검증
- 대결자 알림 추가 시 기존 `lib/approval/engine.ts`의 `notifySubmitted` 호출부를 수정해야 하므로, module-2~9 전체에 영향 — 회귀 테스트(`npm run smoke`) 필수 재실행
