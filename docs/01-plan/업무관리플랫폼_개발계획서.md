# 업무관리 플랫폼 개발계획서 (Plan)

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 업무관리 플랫폼 (가칭: nuGW) |
| 작성일 | 2026-08-13 |
| 문서 단계 | PDCA - Plan |
| 대상 | 연차(휴가)관리 + 결재 시스템 + 일일/주간 업무보고 |
| 플랫폼 형태 | 웹(반응형) 단일 서비스 |
| 결재 구조 | 부서별로 다른 유동적 결재선 (관리자가 결재라인 구성) |

## 1. 배경 및 목적

기업 내 반복적으로 발생하는 두 가지 행정 업무 — **① 연차(휴가) 신청/승인**, **② 일일·주간 업무보고 작성/결재** — 를 하나의 웹 플랫폼에서 처리하여 종이/메신저/엑셀 기반의 비효율을 제거하고, 결재 이력과 근태 데이터를 체계적으로 관리하는 것을 목적으로 한다.

핵심 설계 원칙:
- **필수 기능 중심(MVP)**: 없어도 되는 기능은 과감히 후순위로 미루고, "신청 → 결재 → 이력 조회"가 끊김 없이 도는 것을 최우선으로 한다.
- **조직 유연성**: 부서마다 결재선이 다르므로, 결재 라인은 하드코딩이 아니라 관리자가 설정하는 데이터로 다룬다.
- **이중 연차 산정 기준**: 회사(또는 부서) 단위로 "회계연도 기준" / "입사일 기준" 중 선택해 운영할 수 있어야 한다.

## 2. 핵심 기능 정의

### 2.1 연차(휴가) 관리

| 구분 | 내용 |
|---|---|
| 연차 산정 기준 선택 | 회사 설정값으로 **회계연도 기준**(예: 매년 1/1 일괄 갱신) 또는 **입사일 기준**(개인별 입사일마다 갱신) 중 택1. 신규 입사자 비례 계산(월할/일할) 포함 |
| 연차 발생 로직 | 근속연수 구간별 발생일수 테이블 관리(예: 1년 미만 월 1일, 1~3년 15일, 이후 2년마다 +1일 등 회사 정책값으로 관리) |
| 신청 유형 | **연차(일)**(시작일/종료일 지정, 근무일수 산정) / **연차(시간)**(날짜+시작·종료시간 지정, 정시 단위) / 공가 / 경조사 등 특별휴가 / 병가 — **3개 카테고리로 구분 관리**(아래 표 참조). 기존의 오전반차·오후반차·반반차 고정 단위는 **연차(시간)으로 통합**하여 폐지 |
| 신청 유형 구분 | **① 연차 차감형**(연차(일)·연차(시간) — 잔여연차에서 차감) / **② 특별휴가**(경조사 등 — 차감하지 않는 별도 항목으로 뭉뚱그려 관리, 상세 한도는 결재자 재량 판단) / **③ 공가**(예비군훈련·건강검진·투표 등 법정·공식 사유 — 차감하지 않음). 관리자가 유형별로 이 중 어느 카테고리에 속하는지 설정 |
| 연차(시간) 계산 규칙 | 시작·종료시간은 **정시 단위로만 선택**. 신청 구간이 **점심시간(회사 설정값, 기본 12:00~13:00)과 겹치면 해당 시간을 자동 제외**하고 실사용 시간을 계산. 신청 가능 시간은 **회사 설정 단위(기본 2시간)의 배수**만 허용하며, **상한(기본 6시간) 초과 시 상신 자체를 차단**하고 연차(일)로 신청하도록 안내. 잔여연차 차감은 `사용시간 ÷ 1일 환산 기준시간(회사 설정, 기본 8시간)`으로 환산해 **일(日) 단위로만** 표시·차감 |
| 증빙서류 첨부 | **특별휴가·공가 신청 시 증빙파일 첨부**(예비군훈련확인서, 진단서, 청첩장 등). 연차 차감형은 첨부 불필요 |
| 급여 유형(유급/무급) | 연차 차감 여부와는 **별개 축**으로, 유형별 유급/무급 여부를 관리자가 설정. 기본값: 연차·특별휴가·공가는 유급, **병가는 무급**(회사 정책값으로 변경 가능) |
| 신청 프로세스 | 유형 선택 → 기간(일자/시간) 선택 → 사유 입력 → 잔여연차 자동 검증 → 결재선 자동 매칭 → 상신 |
| 잔여연차 조회 | 개인별 발생/사용/잔여 현황, 유형별 사용 내역, 팀 전체 연차 캘린더(동료 휴가 확인) |
| 회수/취소 | 승인 전 신청 회수, 승인 후 취소는 재결재 프로세스 |
| 대기중 수정 | **결재자가 아직 아무도 처리하지 않은 대기 상태에서는 신청자가 직접 수정도 가능**(취소와 동일 조건). 결재가 한 단계라도 진행된 뒤에는 수정 불가 |

### 2.2 결재(승인) 시스템 — 공통 엔진

연차 신청과 업무보고 결재가 **동일한 결재 엔진**을 공유하는 구조로 설계한다.

| 구분 | 내용 |
|---|---|
| 결재선 구성 | 관리자가 **부서별로 결재 라인(1차/2차 승인자, 병렬/직렬 여부)을 자유롭게 설정**. 문서 종류(연차/일보/주보)마다 다른 결재선 지정 가능 |
| 결재 상태 | 임시저장 → 상신(대기) → 승인/반려 → (필요 시) 최종 확인 |
| 위임/대결 | 승인권자 부재 시 대결자 지정 |
| 알림 | 상신/승인/반려 시 알림(이메일 및 앱 내 알림) |
| 이력 관리 | 모든 결재 행위(일시, 처리자, 의견) 로그 보존 |
| 대기중 수정·취소 무결성 | 연차·일일보고·주간보고·초과근무 모두 **결재 진행 전(대기, 미처리)에는 신청자가 직접 수정/취소 가능**. 신청자의 수정 시점과 결재자의 승인 시점이 겹칠 경우를 대비해 **버전 기반 동시성 검증**을 적용 — 결재자가 오래된 내용을 보고 승인하거나, 이미 승인된 건이 뒤늦게 수정되는 상황을 방지(설계서 §4.7) |

### 2.3 일일업무보고

| 구성 항목 | 내용 |
|---|---|
| 당일 업무실적 | 오늘 수행한 업무 내용 |
| 다음날 업무계획 | 내일 예정된 업무 내용 |
| 보고사항 | 특이사항, 공유가 필요한 이슈 등 자유 기재 |

**자동 초안(Draft) 규칙 — 필수 핵심 로직**
- 일일업무보고를 새로 작성할 때, **"당일 업무실적" 항목의 초안은 전일(직전 영업일) 일일업무보고의 "다음날 업무계획" 내용을 자동으로 가져와 채운다.**
- 사용자는 초안을 그대로 제출하거나 자유롭게 수정할 수 있다(실제 수행한 내용과 계획이 다를 수 있으므로 수정 가능해야 함).
- 전일 일일업무보고가 없는 경우(최초 작성, 휴가/공휴일 등으로 미작성) 당일 업무실적은 빈 값으로 시작.
- "다음날 업무계획"과 "보고사항"은 매번 신규 입력.

| 구분 | 내용 |
|---|---|
| 제출/결재 | 작성(자동초안 확인·수정) → 상신 → 결재선(팀장 등) 승인 |
| 조회 | 본인 작성 이력, 팀장 입장에서 팀원 일보 목록 조회 |
| 휴가 연계 표시 | 전일이 본인 휴가였다면 안내 배지 표시(자동 초안이 비어있는 이유를 알 수 있음), 캘린더(2.7)와 연동 |

### 2.4 주간업무보고

| 구성 항목 | 내용 |
|---|---|
| 금주 업무실적 | 해당 주(월~금 등 회사 기준 주간 범위) 실적 |
| 차주 업무계획 | 다음 주 예정 업무 |
| 보고사항 | 특이사항, 공유가 필요한 이슈 등 자유 기재 |

**자동 초안(Draft) 규칙 — 필수 핵심 로직**
- 주간업무보고를 새로 작성할 때, **"금주 업무실적" 항목의 초안은 해당 주간에 작성된 일일업무보고들의 "당일 업무실적" 내용을 모아(취합) 자동으로 채운다.**
- 사용자는 취합된 초안을 그대로 제출하거나 자유롭게 수정·정리(요약, 항목 정리 등)할 수 있다.
- "차주 업무계획"과 "보고사항"은 매번 신규 입력.
- 해당 주간에 일일업무보고가 없는 날(공휴일, 미작성 등)은 집계에서 자연히 제외.

| 구분 | 내용 |
|---|---|
| 제출/결재 | 작성(자동 취합초안 확인·수정 → 차주계획·보고사항 입력) → 상신 → 결재 |
| 조회 | 주차별 이력 조회, 팀 단위 취합 뷰 |
| 휴가 연계 표시 | 해당 주간에 본인 또는 팀원의 승인된 휴가가 있으면 인원·일자 배지로 표시, 캘린더(2.7)와 연동 |

### 2.5 관리자(시스템관리자) 기능

일반 사용자 메뉴와 분리된 **관리자 전용 영역**으로 운영한다. 본 플랫폼은 **단일 회사 전용**(사내 시스템)으로 운영하며, 여러 회사가 각자 관리자를 두는 멀티테넌트 구조는 범위에 포함하지 않는다.

| 구분 | 내용 |
|---|---|
| 회사 기본정보 | 회사명, 사업자등록번호, 대표자, 근무제(주 5일 등), 전사 기본 연차산정기준(회계연도/입사일 중 기본값), **1일 환산 기준시간(기본 8시간)**, **점심시간(기본 12:00~13:00)**, **연차(시간) 신청 단위(기본 2시간)·상한(기본 6시간)** 등록·수정. 시스템 전체에서 1건만 존재하는 설정값 |
| 조직 관리 | 부서(계층형) 등록/수정, 부서별 연차산정기준 오버라이드(전사 기본값과 다르게 설정 가능) |
| 사용자 관리 | 계정 등록/수정, 소속 부서·직급·입사일 관리, 권한 부여(일반 사용자 / 결재자 / 관리자 3단계), 퇴사 처리 |
| 결재선 관리 | 부서 × 문서유형(연차/일보/주보)별 결재 라인 등록/수정 (2.2와 연결되는 핵심 관리 기능) |
| 연차정책 관리 | 근속연수별 발생일수 테이블, 연차 유형(위 2.1 신청 유형 구분 표의 3개 카테고리) 등록·수정, 유형별 증빙 첨부 필수 여부 설정 |

### 2.6 대시보드 & 알림

| 구분 | 내용 |
|---|---|
| 개인 대시보드 | 내 잔여연차, 최근 신청 현황, 미결 결재함(승인 대기) |
| 결재자 대시보드 | 처리해야 할 결재 목록(연차/일보/주보 통합) |
| 알림 | 상신/승인/반려/기한 임박 알림 |

### 2.7 일정관리(캘린더)

| 구분 | 내용 |
|---|---|
| 캘린더 범위 | **전사 통합 캘린더 1개**(월간 뷰). 부서별로 캘린더를 분리하지 않고, 조회 시 부서 필터만 제공 |
| 휴가 자동 표시 | 승인된 연차·특별휴가·공가가 날짜에 **구성원 이름과 함께 자동 표시**(연차관리와 연동, 별도 입력 불필요) |
| 사내 일정 등록 | 제목·날짜/시간·장소·설명을 입력해 **전 직원이 회의/행사 등 일정을 등록** 가능. 본인이 등록한 일정만 수정·삭제 가능(관리자는 전체 일정 관리 가능) |
| 업무보고 연계 | 일일/주간업무보고 작성 화면에서 해당 날짜(주간)에 본인 또는 팀원의 승인된 휴가가 있으면 배지로 표시 — 예: 전일이 본인 휴가였다면 "전일은 휴가였습니다" 안내, 팀원 휴가 인원수 표시 |

### 2.8 출퇴근 관리(근태)

| 구분 | 내용 |
|---|---|
| 출근/퇴근 체크 위치 | **개인 대시보드**에 배치(별도 메뉴 이동 없이 당일 체크를 바로 처리). 출근은 당일 최초 1회, 퇴근은 **18:00 이후에만 버튼 활성화**(이전엔 비활성 + 사유 안내) |
| "출퇴근" 메뉴 | 체크 기능이 아닌 **월별 근태 조회 화면**. 조회 년월 선택(기본값: 당월), 본인의 일자별 출근/퇴근/휴가 현황과 월간 요약(출근일수/휴가일수/미체크일수) 표시 |
| 관리자 조회 권한 | **관리자는 "출퇴근" 메뉴에서 전 직원의 월별 근태기록을 조회 가능**(구성원 목록 → 개인 상세 드릴다운) |
| 휴가 연동 표시 | 연차관리(2.1)에서 승인된 휴가가 있는 날은 근태기록에 유형과 함께 자동 표시하고, **병가는 "무급" 표시**를 함께 노출(2.1의 급여 유형 설정과 연동) |
| 퇴근 시간대별 규칙 | 18:00~19:00은 누구나 퇴근 체크 가능. **19:00 이후 퇴근 체크는 당일 승인된 초과근무 신청(2.10)이 있는 경우에만** 가능 |
| 자동 퇴근 처리 | 퇴근 체크 없이 18:30이 경과하면(당일 승인된 초과근무가 없는 경우에 한해) **퇴근시간을 18:00으로 자동 저장**하고 근태기록에 "자동" 표시 |

### 2.9 인사기록카드(개인정보 관리)

| 구분 | 내용 |
|---|---|
| 접근 경로 | 사이드바 좌측 하단 **사용자 아이콘 클릭 → "인사정보" / "로그아웃" 메뉴** 노출 |
| 작성 주체 | **본인이 직접 입력**(표준서식) |
| 구성 항목 | 기본 인적사항(사진·성명·생년월일·성별·연락처·주소·비상연락처), 학력사항, 경력사항, 자격/면허사항, 병역사항, 가족사항, 서약 |
| 개인정보 처리 | 주민등록번호 전체 수집은 지양하고 **생년월일**로 대체(개인정보보호법 최소수집 원칙) |
| 저장 | 서약 체크 후 저장, 저장 이력(최종 저장일시) 표시 |

### 2.10 초과근무 신청

| 구분 | 내용 |
|---|---|
| 신청 항목 | 날짜, 예상 퇴근시간(19:00 이후로만 입력 가능), 업무내용(상세), 사유 |
| 결재 | **반드시 결재 승인이 있어야 함**(연차·업무보고와 동일한 공통 결재 엔진 재사용) |
| 근태 연동 | 승인된 신청이 있는 날에만 본인이 19:00 이후 퇴근 체크 가능(2.8과 연동) |

> **MVP 범위 기준**: 위 2.1~2.10 전부가 "필수" 범위이며, 이 중에서도 우선순위는 **① 조직/결재선 기반 구조 → ② 연차 신청·승인 → ③ 캘린더(연차 연동) → ④ 출퇴근 체크·초과근무 신청 → ⑤ 일일보고 → ⑥ 주간보고(일보 연동) → ⑦ 대시보드/알림 → ⑧ 인사기록카드** 순으로 개발한다. 통계/리포트 다운로드, 모바일 앱, 전자결재 외부연동(그룹웨어 SSO 등)은 2차 확장 범위로 분리한다.

## 4. 기술 스택 추천

조직 규모가 크지 않고(부서 단위 유동 결재선 정도의 복잡도), 별도 인프라 운영 인력을 두기보다 **빠른 구축과 낮은 운영 부담**이 중요한 프로젝트 성격이므로 다음을 추천한다.

| 영역 | 추천 | 이유 |
|---|---|---|
| 백엔드/DB/인증 | **bkend.ai (BaaS)** | 사용자 인증, 데이터 모델(테이블), API를 서버 구축 없이 빠르게 구성. 결재/연차처럼 관계형 데이터(부서-사용자-결재선-신청-결재이력)가 많은 도메인에 적합 |
| 파일 저장 | **bkend.ai Storage** | 증빙파일 업로드를 presigned URL 방식으로 처리, CDN으로 다운로드 — 별도 파일 서버 불필요 |
| 프론트엔드 | **Next.js (React) + 반응형 UI** | 웹 단일 플랫폼 요건에 부합, SSR로 초기 로딩/SEO 이점(사내 시스템이라 SEO는 우선순위 낮지만 성능 이점은 유지) |
| 배포 | Vercel 등 정적/서버리스 배포 | 별도 서버 운영 불필요, bkend.ai와 궁합 좋음 |

이 조합은 bkit의 **Dynamic 레벨**(로그인 + DB + 풀스택)에 해당한다. 향후 조직 규모가 커지거나(다수 계열사, 그룹웨어 연동, 대용량 트래픽) 자체 인프라·커스터마이징이 필요해지면 그때 Enterprise 레벨(자체 서버/DB, MSA)로 전환을 검토한다. 지금 단계에서 Enterprise로 시작하는 것은 과설계(over-engineering)로 판단된다.

## 5. 데이터 모델 초안 (설계 단계에서 상세화)

- `CompanySettings` (회사 기본정보: 회사명, 사업자등록번호, 대표자, 근무제, 전사 기본 연차산정기준 — 시스템 내 1건)
- `User` (사용자: 이름, 이메일, 부서, 직급, 입사일, 역할, 재직상태)
- `Department` (부서: 계층 구조, 연차산정기준[회계연도/입사일, 전사 기본값 오버라이드])
- `ApprovalLine` (결재선: 문서유형별, 부서별 1차/2차 승인자 설정)
- `LeavePolicy` (연차 정책: 근속연수 구간별 발생일수, 반차/반반차 단위 설정)
- `LeaveTypeConfig` (연차 유형: 연차차감형/특별휴가/공가 3개 카테고리, 유형별 증빙 첨부 필수 여부)
- `Attachment` (증빙파일: 연차 신청 참조, 파일명, 파일 URL, 업로드 일시)
- `Event` (사내 일정: 제목, 일시, 장소, 설명, 등록자, 부서 필터용 태그[선택])
- `AttendanceRecord` (근태기록: 사용자, 일자, 출근시각, 퇴근시각, 상태)
- `HrRecord` (인사기록카드: 사용자, 기본 인적사항, 학력/경력/자격/병역/가족사항, 서약 여부, 최종 저장일시)
- `OvertimeRequest` (초과근무 신청: 사용자, 날짜, 예상 퇴근시간, 업무내용, 사유, 상태)
- `LeaveBalance` (개인별 연차 발생/사용/잔여 현황)
- `LeaveRequest` (연차 신청: 유형, 기간, 사유, 상태)
- `DailyReport` (일일업무보고: 작성자, 대상일자, 당일업무실적, 다음날업무계획, 보고사항, 상태) — 등록 시 전일 `DailyReport.다음날업무계획` → 당일 `당일업무실적` 초안 자동 매핑
- `WeeklyReport` (주간업무보고: 작성자, 대상주차(시작~종료일), 금주업무실적, 차주업무계획, 보고사항, 상태) — 등록 시 해당 주차 `DailyReport.당일업무실적` 목록 → `금주업무실적` 초안 자동 취합
- `Approval` (결재 이력: 문서 참조, 처리자, 처리결과, 의견, 처리일시) — 연차/일보/주보 공통 사용

## 8. 리스크 및 고려사항

- **연차 산정 로직 복잡도**: 회계연도/입사일 두 기준을 동시에 지원해야 하므로 초기 정책 설계(법정 연차 규정 반영 여부 포함)를 명확히 확정하고 시작해야 함 → 설계 단계에서 HR 담당자 확인 필요
- **결재선 유연성**: "부서별로 다름"이 어느 수준까지 유동적이어야 하는지(부서장 임의 설정 vs 관리자만 설정) 설계 단계에서 확정 필요
- **일보/주보 자동 초안 로직의 기준 시점**: "전일 일일보고"의 기준(직전 영업일 vs 캘린더상 어제, 미작성/결재반려 상태의 전일 보고도 초안 소스로 인정할지)과, 주간보고 작성 시점에 해당 주 일일보고가 전부 상신되지 않은 경우(예: 금요일 오전에 미리 작성) 처리 방식을 설계 단계에서 확정 필요
