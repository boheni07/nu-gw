### 1.3 Value Delivered

| 관점 | 내용 |
|---|---|
| **Problem** | 연차/업무보고가 종이·메신저·엑셀로 분산 관리되어 이력 추적과 결재가 비효율적이었고, 팀원 휴가·사내 일정을 한눈에 볼 곳이 없었음 |
| **Solution** | 공통 결재 엔진(ApprovalLine+Approval, 병렬 승인 지원) 위에 연차관리(3카테고리 구분+증빙)·캘린더(휴가 자동 연동)·근태/초과근무·일일/주간 업무보고를 얹어 하나의 플랫폼으로 통합 |
| **Function/UX Effect** | 부서별 유동 결재선(병렬 승인 포함), 이중 연차 산정, 연차(시간) 자동 계산(점심시간 제외), 일보→주보 자동 취합, 전일 휴가 시 자동 안내 배지, 캘린더 자동 병합, 알림 3종 자동 발송, §4.7 버전 기반 동시성 제어로 결재 중 충돌 방지 |
| **Core Value** | 행정 처리 시간 단축 + 결재/근태 이력의 체계적 데이터화 + 연차 차감 오류 방지(자동 계산·환원) + 팀 일정 가시성 확보 + 재실행 가능한 회귀 테스트로 향후 변경에 대한 안전망 확보 |

## 2. Key Decisions & Outcomes

| 단계 | 결정 | 근거 | 실제 이행 결과 |
|---|---|---|---|
| Plan | 기술스택: bkend.ai(BaaS) + Next.js 추천 | 빠른 구축, 낮은 운영 부담 | **변경됨** — 사용자 요청으로 module-1 착수 시점에 로컬 파일 저장소(JSON) + 로컬 파일 스토리지로 전환. 결과적으로 외부 서비스 의존 없이 전체 스택이 자체 완결적으로 동작 |
| Design | Option C(실용적 균형) — ApprovalLine+Approval 2테이블 공통 결재 엔진 | 문서 종류 확장 시 재사용성 확보 | ✅ 그대로 구현. module-3(연차)/5(초과근무)/6(일보)/7(주보) 4종 문서가 전부 동일 엔진을 재사용함을 curl로 직접 검증 |
| Design §4.7 | 버전 기반 낙관적 동시성 제어 | 결재 중 신청 내용이 바뀌는 상황 방지 | ✅ LeaveRequest/DailyReport/WeeklyReport 전부 구현, 스모크 테스트에 포함되어 회귀 시에도 자동 검증됨 |
| Design §3.2 | 병렬 승인(isParallel) | 동일 단계 복수 승인자 지원 | ✅ Check 단계에서 미구현으로 지적되어 Act 단계에서 구현 완료 — 동일 stepOrder 전원 승인 시에만 다음 단계로 이동 |
| module-5 범위 결정 | OvertimeRequest를 Design 8-모듈 지도에 명시적 배정이 없었으나 module-5(근태)에 편입 | 19:00 이후 퇴근 게이트 로직이 초과근무 승인 여부에 의존해 분리 불가능 | ✅ 편입 후 정상 동작, 근태-초과근무 연동 검증 완료 |
| Check 단계 | Match Rate 87% → Act로 4개 Important 이슈 즉시 수정 결정(사용자 선택) | 조직관리 UI/수정폼/병렬승인/자동테스트 부재 | ✅ 1회 Act로 전부 해결, Match Rate 95%로 상승 |
