## 7. 종합 판단(최초 분석 시점)

- **핵심 기능은 전 모듈에 걸쳐 견고하게 동작**한다 — 8개 모듈 모두 실제 서버 구동 후 curl+브라우저로 라이프사이클 전체(정상/에러/권한/동시성 케이스 포함)를 검증했다.
- Match Rate가 90%에 못 미치는 주된 이유는 **자동화 회귀 테스트 부재**, **조직 관리 UI 누락**, **수정 폼 간소화**, **병렬 승인 미구현** 4가지로 명확하다.
- Critical 이슈는 없다 — 전부 Important 이하이며, 서비스 운영 자체를 막는 결함은 아니다.

## 8. Act(반복 개선) 반영 결과 — 2026-08-19

사용자가 "Important 4건 모두 수정"을 선택해 즉시 Act를 진행했다. 별도 반복 사이클(iterate) 없이 1회차에 4건 모두 해결했다.

| # | 이슈 | 조치 | 검증 방법 |
|---|---|---|---|
| 1 | 조직 관리 UI 부재 | `admin/departments` 화면 신규 구현(부서 등록, 상위부서 계층 선택, 연차산정기준 오버라이드) | 브라우저로 부서 등록·오버라이드 설정 확인 |
| 2 | 수정 폼 간소화 | LeaveRequest/DailyReport/WeeklyReport의 "수정"을 `prompt()`에서 **신규 신청 폼 전체 재사용**(§4.7 UX 원칙)으로 교체 — 기존 값 프리필, 제출 버튼 "수정 저장"으로 변경 | 브라우저로 수정 진입 시 기존 값이 채워진 폼이 열리는지 확인 |
| 3 | 병렬 승인 미구현 | `lib/approval/engine.ts`에 stepOrder 그룹 개념 도입 — 동일 단계 승인자 전원이 승인해야 다음 단계로 이동. 관리자 결재선 설정 화면에 "병렬 승인자 추가" UI 추가 | curl로 2인 병렬 결재선 구성 → 1명 승인 후에도 PENDING 유지, 재승인 차단(409), 2번째 승인 후 최종 APPROVED까지 전 과정 검증 |
| 4 | 자동화 테스트 부재 | `scripts/smoke-test.mjs` 신규 작성(`npm run smoke`) — 인증/RBAC, 연차 신청·승인·반려·환원, §4.7 동시성, 일일보고 자동초안, 캘린더 병합, 알림, 근태를 25개 어서션으로 검증 | 실제 실행 — **25/25 통과** |

**부수 효과**: 스모크 테스트 작성 과정에서 테스트 자체의 검증식 버그(반려 시 잔여연차 스냅샷 시점 오류)를 발견해 수정함 — 앱 코드에는 결함 없음을 재확인.

### Match Rate 재계산

| 축 | 이전 | 이후 | 근거 |
|---|---|---|---|
| Structural | 90% | 98% | 조직 관리 UI 추가로 Design §2.5 요구 화면 전부 충족 |

### 잔존 Minor 이슈(6건, 유지)

DRAFT 상태 미사용, 증빙파일 업로드 API 계약 변경, 자동 퇴근 처리 지연계산, `DUE_SOON` 알림 미구현, 팀장용 팀원 일보 이력 뷰 없음, 인사기록카드 미구현. 전부 서비스 운영을 막지 않는 수준이며, 이번 Act 범위에는 포함하지 않았다(사용자가 Important 4건만 선택).
